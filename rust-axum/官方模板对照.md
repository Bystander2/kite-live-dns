## 代理、结算与错误边界

| 行为 | 官方参考 | Rust 0.1.1 | 证据或差异 |
| --- | --- | --- | --- |
| 请求顺序 | verify → upstream → settle | 相同 | paid_proxy_orders_verify_upstream_settle |
| 未付款隔离 | 不调用上游 | 相同 | unpaid_402_does_not_call_services |
| 验证失败 | 付款被拒绝，不调用上游 | 402，保留 invalidReason | invalid_payment_does_not_proxy；SDK 的完整错误正文未对比 |
| 上游 503 | 不结算 | 原样返回 503，不结算 | upstream_failure_does_not_settle |
| 结算失败 | 不应返回付费成功 | 402，保留 errorReason，隐藏成功正文 | failed_settlement_withholds_upstream_success；SDK 的完整错误正文未对比 |
| 网络故障 | Express 上游 fetch 失败返回 502 | 上游/verify/settle 通信失败返回 502，使用不同错误字符串 | Rust 源码确认；通信失败分支尚无专门断言 |
| 结算成功状态范围 | 官方 README 为 <400 | Rust 仅 2xx | 明确差异：Rust 的 3xx 不结算 |
| 重定向 | Express fetch 默认跟随；Gin reverse proxy 返回重定向 | Rust 不跟随 | 官方两模板本身也不完全一致；Rust 更接近 Gin 的转发方式，但 3xx 结算条件不同 |
| 上游基础路径 | Express 绝对请求路径替换基础路径；Gin reverse proxy 拼接基础路径 | 保留基础路径并追加去掉 /v1/ 的后缀 | 更接近 Gin；现有测试验证 /base/records |
| 方法与正文 | 模板保护所有方法并代理 | Axum any；正文最多 2 MiB | GET 已验证；其他方法未逐个运行验收；Vercel 桥接缺 OPTIONS/TRACE handler |
| 支付与连接头 | 删除付款签名和部分 hop-by-hop 头 | 删除更多支付头及 Connection 指定头；覆盖配置的上游鉴权头 | CI 断言；加强过滤是明确差异 |
| 超时与响应缓冲 | 官方实现与 SDK 的默认值各异 | reqwest 20 秒；完整读取响应后结算 | Rust 源码确认，不宣称超时一致 |
| 免费健康检查 | ok/network/asset/price | ok/network/runtime/price；没有 asset，price 无自动美元前缀 | 免费 200 一致，JSON 字段不同 |
| 公网 resource URL | 框架/SDK 生成 | Rust 从 URI/Host 构造，默认 http | Vercel HTTPS 请求的挑战中仍显示 http；不影响本次结算，但元数据有待修正 |
| facilitator 支持发现 | 官方 SDK 使用 /supported；Gin 启动同步 | Rust 直接 /verify 和 /settle，无 /supported 同步 | 实现差异，真实测试网支付可用 |
| 价格及地址校验 | 官方 SDK/模板校验 | Rust 拒绝零价、过精度、超大金额、零地址等 | 主网精度错误有断言，其余边界主要为源码检查 |

## 结论与剩余项

模板、配置、主要支付流程、发布和测试网真实付款证据齐备。此次对照发现边界差异，因此“完整对照记录已完成”不等于“所有行为一致性验收已通过”。

后续若要求严格等价，应先明确以 Express 还是 Gin 为基准，再处理或确认：3xx 结算策略、基础路径及重定向、健康响应、错误正文、/supported、方法覆盖和代理协议元数据。需要为这些边界补差分运行证据；不能仅凭现有 6 项测试宣称全部一致。本次只增加记录，没有修改发布包、部署代码或重新付款。

## 0.1.2 兼容性修订（提交 167cbbe）

以官方 Gin 及其锁定的 Coinbase SDK `30e01607975e` 为行为参考。
[SDK 结算处理](https://github.com/coinbase/x402/blob/30e01607975e/go/http/server.go)
和 [Gin 中间件](https://github.com/coinbase/x402/blob/30e01607975e/go/http/gin/middleware.go) 已直接核对。
上方表格保留为 0.1.1 的历史快照，以下修订覆盖对应差异。

- 上游状态 <400 才结算；3xx 不跟随，返回原始重定向，与 Gin 的非错误状态结算规则一致。
- 结算失败返回 402、空对象正文和 base64 PAYMENT-RESPONSE，包含 success=false、errorReason、network、payer 和空 transaction；网络通信失败也进入此失败结算路径。
- 健康响应增加 asset，price 规范为美元前缀；保留 runtime 扩展字段。
- UPSTREAM_AUTH_VALUE 和 PORT 空白处理与官方环境变量读取方式对齐。
- Vercel 增加 OPTIONS/TRACE；HTTPS 桥接使用绝对 URI 传递公共协议，Rust 不信任任意买方的 X-Forwarded-Proto。
- 原有基础路径保留、禁止重定向行为与 Gin 对齐，无需改成 Express 的行为。
- 新增回归断言：3xx 顺序、POST/PUT/PATCH/DELETE/OPTIONS/TRACE 的方法和正文、两链健康字段、HTTPS URL、防伪造转发头、畸形签名；强化失败结算头和空正文断言。

仍有明确限制：未实现 SDK 的浏览器 HTML paywall 和 /supported 能力缓存同步；严格地址/URL 校验、2 MiB 请求上限、额外头过滤和超时仍是 Rust 的实现策略。验证失败及通信错误文案不保证与 SDK 逐字一致。此次不是所有 SDK 功能的移植，不宣称全量字节级等价。新版本的付款行为变更需部署后再次验证；0.1.1 的真实付款回执不冒充 0.1.2 的付款证据。

公网复核：新版 /healthz 已返回 asset=pieUSD、price=$0.001；402 resource URL 为 HTTPS，OPTIONS 返回 402。Vercel 边缘直接拒绝 TRACE（405 NOT_ALLOWED），不是 Rust handler 的返回；核心 TRACE 代理测试通过。故 Vercel 部署无法证明全方法与 Gin 完全一致，需要支持 TRACE 的宿主才能暴露该方法。
